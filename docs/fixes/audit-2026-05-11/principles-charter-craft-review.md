## §1 问题意识

### 1.1 为什么有第四轮重审

`principles.md` 在 P10 之后两个月内经历了**四种不同视角的审视**：

| 轮次 | 视角 | 主要产出 | 核心立场 |
|---|---|---|---|
| audit-1 | 补漏（"还应该加什么"） | `principles-review.md` 463 行 | 4 条修宪议案（加法主导） |
| counter-1 | 驳证（"audit 是不是错了"） | `counter-challenge/audit-1-counter.md` 443 行 | 8/14 成立、4 议案全部前提不成立 |
| okkam-review | 减法（"还能剃多少"） | `principles-okkam-review.md` 1103 行 | 30 条剃项议案、草稿 75 行（剃幅 77%） |
| **charter-craft（本轮）** | 制宪方法学综合 | 本文 | 问题驱动 + 奥卡姆 + 清晰 + 二元结构 |

**前三轮各自的方法论缺口**：

- **audit-1 偏加法、偏修宪**——counter-1 已证明"4 议案前提全部不成立"，audit-1 把"实施细节漂移"过度推论为"需要修宪"，反映其方法论默认是"宪法 enumerate 实施"
- **counter-1 偏防御**——只问"audit 错没错"，没问"现状本身应该长什么样"，**接受了 principles.md 当前形态作为论证起点**
- **okkam-review 偏剃**——给出了 75 行草稿但**没明示"剃的判据是什么"**，剃 30 条用的是"重复 / 过细 / enumerate"几类经验标准，未系统对照"问题意识 / 防腐蚀"元判据；§3 列 30 条 + §5 75 行草稿后**自身就有 1103 行**，已陷入"审 1 改 3"

**本轮 charter-craft 的方法论补位**：

charter-craft 不是 audit / counter / okkam 三方法的最大公约数，而是**升一层用问题驱动 + 二元结构重审**：

- 问题驱动 = §1.3 元判据"每条规则服务什么问题 / 防什么腐蚀"
- 奥卡姆 = §1.5.1 不仅适用规范核心、也适用经验实践
- 清晰原则 = §1.5.2 制定人清晰 + 后来者清晰**双层**
- 二元结构 = §11 规范核心（精神 + 不可让渡） + 经验实践（可演化）

四个维度系统重审后，会发现 audit-1 / counter-1 / okkam-review **都在"经验实践层"内打转**，没有触及"哪些是真正的规范核心、哪些是经验实践应下沉"这一根本划界。这才是本轮最关键的贡献。

### 1.2 本轮不解决什么

- 不替用户拍板修宪——按 charter-craft §2.2 / §6.4 修宪必须用户显式确认
- 不评价 P15/P16 实施现状的对错——只看宪法文本本身的形态学健康度
- 不进入"详细 fix 清单"——audit-1 已给出 30 行级 fix 表、okkam-review 给出 30 条剃项；本轮仅给"宪法形态学诊断"

## §2 审视方法

按 charter-craft 六维标准（任务书 §审视方法 1-6）：

1. **问题意识审视**（§1.2 + §1.3）：开头是否明示根本问题？每条款是否服务该问题？
2. **奥卡姆审视**（§1.5.1）：冗余必剃，包括规范核心层与经验实践层
3. **清晰原则审视**（§1.5.2 双层）：制定人清晰 + 后来者清晰
4. **规范核心 vs 经验实践划界审视**（§11.1 + §11.2）：哪些段是精神 / 不可让渡 / 边界？哪些段是分析框架 / enumerate / 流程指令应下沉？
5. **反模式扫描**（§5 七条）：修修补补 / 工程现实绑死 / enumerate / 流程指令 / 派生再细化 / 分析框架入宪 / 意图未确认就拟稿
6. **二元结构审视**（§11）：当前 principles.md 是否符合"核心稳定 + 实践演化"？

**诚实底线**（charter-craft §0.3）：

- 不把理想当 binary check——"这条不正交？拒绝"是反模式
- 不把篇幅当上限——319 行可以超 200 行基线，但必须能解释为什么超
- 接受不完美 + 接受权衡

每条结论给 principles.md 具体行号 + charter-craft 具体条款号。

### §4.3 操作推荐

**三种路径对比**：

#### 路径 A：直接采纳 okkam-review 75 行草稿（最快，但方法学不完整）

- **优点**：直接得到 75 行精简版；解决了反模式 6（删 5 层 + 投影）+ 反模式 2/3 主要条款
- **缺点**：未做起源对话；草稿 §六 仍有 4 子标题派生再细化痕迹；未处理 "制定人清晰" 溯源问题；未明示规范核心 vs 经验实践划界作为方法

#### 路径 B：用 charter-craft §4 制宪过程从头做起源对话（最完整，但工作量大）

按 charter-craft §4.1-§4.7：

1. **§4.1 起源对话**（5 问）：与用户重确认根本问题 + 痛点 + 边界 + 受众 + 不可妥协价值
2. **§4.2 意图提炼**：目标（一句话）+ 价值（3-5 条）+ 边界（3-5 条）
3. **§4.3 性质提取**：3-7 条根本性质
4. **§4.4 派生原则**：每性质 1-3 条派生
5. **§4.5 冲突消解**：枚举性质间冲突 + 消解规则
6. **§4.6 反模式扫描**：按 §5 清单扫
7. **§4.7 用户最终确认**：逐条意图对齐

- **优点**：完整、可溯源、彻底处理"制定人清晰"问题
- **缺点**：工作量大（一轮起源对话 + 重新拟稿，可能数小时讨论）；可能与现有共识重复（用户在 P4-P10 已多次确认精神，无需从零）

#### 路径 C：以 okkam-review 草稿为骨架 + charter-craft 重审补漏（推荐）

具体步骤：

1. **以 okkam-review 草稿（75 行）为基础形态**
2. **回头做 §4.1 起源对话的 Q4 + Q5**（用户已多次确认 Q1-Q3，但 Q4 谁约束 / Q5 不可妥协价值确实 implicit；这两问明示即可，无需从零重做）
3. **针对草稿 §六 派生再细化痕迹做二次剃**：4 子标题（时空锚定 / oracle 责任 / 前端测量 / 不区分翻译深浅）合并为 2-3 条更直陈
4. **明示规范核心 vs 经验实践划界**：在文首或文末加一段"本文是规范核心，经验实践见 architecture.md / detailed-design.md / tool-integration.md"——按 charter-craft §11.1 二元结构
5. **§六-2 自陈"与 §三-3-2 同义"那条触发的合并**：彻底去同义反复
6. **重命名 §三-2 "原则 A / B"**避免与 §四 命名冲突
7. **用户最终逐条确认**（charter-craft §4.7）

**预期产出**：约 60-80 行的精简宪法 + 明示的"规范核心 vs 经验实践"划界 + 起源对话 5 问完整覆盖。

**推荐路径：C**——综合保留 okkam-review 已有的减法成果 + 补 charter-craft 方法学缺口 + 控制工作量。

## §6 元注：本审视的局限

按 charter-craft §0.3 "接受不完美 + 承认权衡 = 制宪诚实"：

1. **本审仍然在"经验实践层"评估宪法**——本审自身没做起源对话，**对"制定人清晰"的评估是基于 prompt + memory 推测的，不是直接与用户对话**。如果用户认为 5 层 / 投影 / 形式指标 5 类**就是**他的明示意图，本审 §3.3 + §3.5 反模式 7 的诊断就需要修正。
2. **charter-craft 标准本身的潜在盲区**（meta-meta-feedback）：
   - charter-craft §3.1 篇幅基线 50-200 行——但**项目宪法 vs 国家宪法 vs 学术宪法**的篇幅基线可能不同。当前 principles.md 319 行超基线，但相对其覆盖范围（核心模块 1 + 核心模块 2 + 次要模块 3 + 工具方法学 + 5 层精细化 + ...）来看是不是真的过长？charter-craft 没给"覆盖范围 × 篇幅"的细化判据。
   - charter-craft §5 反模式 6 "分析框架入宪"——但有些分析框架（如 §四 A/B/C 三派生原则本身）**就是用户精神 + 防腐蚀承诺**，介于"理论"和"硬约束"之间。**如何区分"健康的分析结构"vs"不健康的分析框架入宪"，charter-craft 给的判据是"理论可质疑 vs 宪法不可违反"——但这条判据应用到具体条款（如 5 层 vs A/B/C）时仍需主观判断**。
   - charter-craft §11.1 二元结构（规范核心 + 经验实践）——但**有些条款界于两层之间**（如 §三-3-2.b "不冤枉"是核心精神还是 oracle 经验？§六-1 前端测量主条是硬指标还是经验方法学？）。charter-craft 给的划界判据"删了它系统精神是否质变"（§3.5）是判断标准，但 charter-craft 没说"边界情况如何处理"。
   - charter-craft §1.5.2 双层清晰原则——但**项目宪法的"后来者"可能比国家宪法的"后来者"更狭窄**（接手项目的开发者 vs 任何公民）。**对项目宪法来说"后来者清晰"是否可以放宽到"理解项目核心目标的开发者能懂"**？charter-craft 没给具体范围。
3. **本审未对照其他可能的方法学**——如果存在其他制宪方法学（非 charter-craft），评估结论可能不同。charter-craft 自身在 §0.2 承认"本 skill 不是宪法之宪法，是 AI 制宪时的工作经验集合"——所以本审视也只是**一种视角**，不是终极判定。
