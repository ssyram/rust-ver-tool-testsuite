## 候选 1（强）：§一 三原则栈「本地性 / 社区惯例 / 最大善意」

**c 路理由**：三条次序栈是 P27 临时分析框架（charter-craft §5「分析框架入宪」反模式），派生答案不该塞进 §一根本问题层；可下沉到 §六 Oracle 责任。

**counter 论证**：

- **counter 1（不是"分析框架"）**：charter-craft §5「分析框架入宪」反例点名"两层张力 / 5 层精细化 / PA/PB/PC..."——这些是**理论命名 / 学术包装**，可质疑可替代。而本地性 / 社区惯例 / 最大善意**不是分析框架，是冲突消解的优先级声明**——属 charter-craft §3.5 入宪法白名单第 5 项（**冲突消解**），§3.4 也明示"性质间天然冲突时，直陈优先级 / 消解规则"。三条次序栈正是这种"直陈优先级"。
- **counter 2（不是派生再细化）**：§一根本问题 2 是「不公信」，要回答"如何不失公信力"必须给消解规则——否则"测量姿势必须站得住"成空话（charter-craft §1.6.4 反空话）。c 路提议"§一 只留一句精神"恰是把宪法变空话。
- **counter 3（user memory 明示价值）**：feedback_unknown_strict_semantics.md 是用户立场——"本地性原则压倒 wrapper 失败归因"是用户硬要求。这正是 charter-craft R2「已文档化 contract」——deliberate 入宪。
- **counter 4（下沉到 §六不解决问题）**：c 路提议下沉到 §六。但 §六 是次要模块的精神；三条次序栈是 §一根本问题的对策，下沉等于把"宪法精神核心"和"次要模块" 混层。

**R 反状态命中**：R2（已文档化 contract）+ R-charter §3.4/§3.5（冲突消解入宪）

**判定**：**不成立 ✗**

**理由**：三条次序是冲突消解优先级，charter-craft §3.4/§3.5 明示这类内容入宪；c 路把"优先级声明"误判为"分析框架"。当前 §一 措辞已是朴素优先级（不是"PA/PB/PC"包装），保留。
